It's not uncommon to encounter encoded JSON strings, embedded in content such as log output, NoSQL database query results and SQL database query results with nested JSON fields.

This JSON has escape sequences (for example: `\"` for double quotes) and also tends to be compressed into one stream of text, with no indentation. This makes it difficult to read and analyse.

JSON like this can be quickly unescaped and formatted nicely, but you need to have the right tools at hand. I did some searching, AI prompting, exploration and trial & error and settled on a couple of practical solutions.

## Example

One recent case I encountered was viewing structured logging output in [DynaTrace](https://www.dynatrace.com/), generated by a .NET Core service via the [Microsoft logging extensions](https://learn.microsoft.com/en-us/dotnet/core/extensions/logging/overview?tabs=command-line), passing a whole object as a parameter, serialised to JSON.

For example, we have a logging statement like this:
```csharp
_logger.LogDebug(
  "Response has {CustomerProfile} customer profile; {OrderCount} orders.",  
  JsonSerializer.Serialize(customerProfile),
  customerOrders.Count
);
```

Producing output like this in a log entry:

Notice the `Message` field containing JSON content with escape sequences, e.g. `\"UserName\":\"conwy\"`.


## Sublime Text and extensions

For now I've settled on [Sublime Text](https://www.sublimetext.com) with [SublimeStringEncode](https://github.com/colinta/SublimeStringEncode), [SublimePrettyJson](https://github.com/dzhibas/SublimePrettyJson) extensions.

I use `StringEncode: JSON Unescape` to unescape then `Pretty JSON: Format JSON` to automatically add spacing and `Set Syntax: JSON` to add syntax highlighting.

This tactic is fast, reliable and private (keeps data locally). Being integrated into Sublime Text makes it easy to fit into my existing folder / file structure.


## Command line

A command line alternative is `jq`.

For example, I can copy and paste the whole string and pipe it to `jq`:

```bash
echo '"{\"UserName\": \"conwy\",\"FullName\": \"Jonathan Conway\",\"Email\": \"jon@conwy.co\"}"' | jq -r '.' | jq '.'
```

Or I can copy it to the clipboard, read (using e.g. `pbpaste` on MacOS) and echo out.

```bash
pbpaste | jq -r '.' | jq '.'
```

The output is neatly indented:

```json
{
  "UserName": "conwy",
  "FullName": "Jonathan Conway",
  "Email": "jon@conwy.co"
}
```


## Web tools and browser extensions

There is a web tool [JSONLint JSON Unescape](https://jsonlint.com/json-unescape), and it also has a [JSONLint Chrome Extension](https://chromewebstore.google.com/detail/json-formatter/ondecobpcidaehknoegeapmclapnkgcl) providing similar functionality. (These were suggested by Claude Code.)

However these might not be suitable for sensitive data that needs to be kept private and/or corporate environments where browser extensions are blocked.


## Asking AI

Claude Code provided useful suggestions, similar to the above.

Prompt

```md
Log lines viewed in Grafana Loki sometimes contain JSON with escape sequences (for example: \" for double quotes) and also tend to be compressed into one stream of text, with no indentation. This makes it difficult to read and analyse. What's the easiest and best way to format and view this JSON in a readable way? That is, without the escaping and with indentation and syntax highlighting?
```


Reply from Claude Opus 5.5:

```md

It depends on whether you want to fix it inside Grafana or just read a line you've copied. I'd set up both. The Grafana fix is best when you're scrolling through many lines, and the clipboard command is quickest for picking apart one line.

1. In Grafana: let Loki un-escape it for you

Grafana usually shows \" because the JSON is stored as a string inside another field, such as {"msg":"{\"user\":...}"}. LogQL can pull that field out and parse it again:

logql
{app="my-service"} | json | line_format "{{.msg}}" | json

- | json parses the outer line. The field values come out already un-escaped.
- line_format "{{.msg}}" makes that inner JSON string the whole log line.
- The second | json turns its keys into fields you can filter on and see when you expand a line.

Then turn on Prettify JSON in Explore → Logs options (Grafana 10.x/11+; in the Logs panel it's under panel options). You'll get indentation, and expanding a line shows every parsed field in a table.

Swap msg for whatever field holds the nested JSON, e.g. message, body or payload.

2. Clipboard to terminal: a jq one-liner (macOS)

Add this to your ~/.zshrc:

pj() {
  pbpaste | jq -R '
    def unwrap: if type=="string" and test("^\\s*[\\[{]")
                then (. as $s | try (fromjson|unwrap) catch $s) else . end;
    . as $l | (try fromjson catch ("\"" + $l + "\"" | fromjson)) | unwrap | walk(unwrap)'
}

Copy a log line in Grafana and run pj. You'll get indented, colour-highlighted JSON. It handles:
- plain JSON
- a whole line that's escaped ({\"level\":\"info\",...})
- JSON strings nested inside fields, at any depth, even when they're escaped twice

I tested it on both kinds of input. For example:

{\"level\":\"info\",\"body\":\"{\\\"a\\\":1}\"}
becomes
{
  "level": "info",
  "body": {
    "a": 1
  }
}

If you don't have jq, install it with brew install jq. Add | less -R if you want to scroll through long output, or pipe it to pbcopy to put it back on the clipboard.

3. No setup: a browser tool

Paste the line into an online tool like jsonformatter.org or the "JSON Unescape" tool on it-tools.tech. You'll often need to click "unescape" before "format." That's fine for occasional use, but avoid it for logs that might hold personal data or secrets, because you'd be pasting them into a third-party site.
```
